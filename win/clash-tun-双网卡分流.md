# USB 共享一插上，公司内网全断：Clash TUN 和 Windows 路由表

> Windows 路由表、0.0.0.0 通配、前缀长度、跃点

## 背景

公司走 Wi-Fi 网卡，能上网，但视频、音乐一类站点访问不了。于是用手机开 USB 网络共享，电脑多出一块网卡，想同时满足三件事：

- `172.16.x.x` 内网走公司 Wi-Fi
- 国内流量走手机 USB
- 国外流量先过 Clash 再从 USB 出去

目标分流是这样：

```text
172.16.0.0/12  ──(不进 TUN)──► WLAN ──► 172.16.19.254
其余（QQ/微信/网页）──► Clash TUN ──► 规则判断
                              ├ DIRECT / CN  ──► 以太网 2 ──► 192.168.169.138
                              └ 代理节点     ──► 以太网 2 ──► 192.168.169.138 再出国
```

看当时的路由表：

```powershell
route print
```


每一行是一条映射：网络目标、网络掩码、网关、接口、跃点数。最上面三条通配 `0.0.0.0`，就是插上 USB 之后的路由表架构：

| 网关            | 接口            | 跃点 | 对应谁                |
| --------------- | --------------- | ---- | --------------------- |
| 198.18.0.2      | 198.18.0.1      | 0    | Clash 虚拟网卡（TUN） |

| 172.16.19.254   | 172.16.19.94    | 45   | 公司 Wi-Fi 内网口     |

这是插入 USB 后的三条网关接口：Clash、USB、公司内网口各一条通配规则。

## 过程中的坑

插上 USB 之后，视频、音乐一类娱乐站点确实能访问了，但内网访问不了。

原因是路由优先级。Windows 不是谁后插上谁说了算，多条路由同时存在时按下面这张表选：

| 比较顺序 | 规则                     | 这张表里的例子                                          |
| -------- | ------------------------ | ------------------------------------------------------- |
| 1        | 前缀更长更精确，优先     | `172.16.19.0/24` 压过 `0.0.0.0/0`                       |
| 2        | 前缀一样，跃点越小越优先 | 三条 `0.0.0.0/0` 一样模糊：Clash 0 > USB 25 > 内网口 45 |

当时表里对公网和其它内网段，实质只有这三条默认通配。没有更精确的 `172.16.0.0/12`，所以流量都会先命中跃点 0，进 Clash 虚拟网卡。Clash 处理完（直连或代理）会自动选一个非自身的网关：USB 或公司 Wi-Fi。USB 跃点 25 < 内网口 45，于是全部指定到 USB。USB 能上外网，所以娱乐站点通了；USB 到不了公司内网，所以内网超时。

举几个目的地址：

| 访问                       | 第一跳（系统路由）         | Clash 出站      | 结果               |
| -------------------------- | -------------------------- | --------------- | ------------------ |
| 视频 / 音乐站点（公网）    | 通配，进 Clash（跃点 0）   | 25 < 45，走 USB | 外网通             |
| QQ / 微信（公网）          | 同上                       | 走 USB          | 外网通             |
| `172.16.9.x`（其它内网段） | 没有精确规则，同样进 Clash | 仍然走 USB      | USB 不通内网，超时 |
| `172.16.19.x`（本网段）    | 前缀 `/24` 更长，不走通配  | 不经过上面那套  | 有时还能通         |

拔掉 USB 后，25 那条没了，Clash 只能选公司 Wi-Fi，内网恢复，外网 IP 变回公司的。再插上，又全部指定到 USB。

## 解决办法

补一条更精确的规则，把内网 IP 指回内网网卡。管理员执行（不要 `-p`，重启后消失，需要再加）：

```powershell
route ADD 172.16.0.0 MASK 255.240.0.0 172.16.19.254 IF 16 METRIC 5
```

`IF 16` 是 WLAN 的接口号，以 `Get-NetAdapter` 为准。`172.16.0.0/12` 覆盖 `172.16.0.0` 到 `172.31.255.255`，不要写成 `172.0.0.0/8`。

加完后表里多了一条比通配更精确的规则，流量过程变成：

| 访问                | 系统路由                                     | Clash                    | 结果                 |
| ------------------- | -------------------------------------------- | ------------------------ | -------------------- |
| `172.16.9.x`        | 命中 `/12`，下一跳 `172.16.19.254`，不进 TUN | 不经过                   | 走公司 Wi-Fi，内网通 |
| `172.16.19.x`       | `/24` 比 `/12` 更长，本网段直连              | 不经过                   | 仍走公司 Wi-Fi       |
| 视频 / 音乐（公网） | 仍是通配，进 Clash（跃点 0）                 | 25 < 45，出 USB          | 外网通               |
| QQ / 微信（公网）   | 同上                                         | 出 USB，规则判直连或代理 | 外网通               |

内网被精确规则拆走，其余还走通配，进 Clash 再出 USB。

Clash 侧可以再排除这段，避免 TUN 先截走。写在 Mihomo Party 的 `mihomo.yaml`:

```yaml
tun:
  auto-route: true
  auto-detect-interface: true
  route-exclude-address:
    - 172.16.0.0/12
```

改完重载内核。

验证：

```powershell
route print -4 | findstr "0.0.0.0 172.16"
tracert -d 172.16.9.1
```

内网第一跳应是 `172.16.19.254`，不应是 USB，也不应是 `198.18.0.2`。

## 小结

系统命令, 管理员权限执行（修改操作需要）:

```powershell
# 查看 网卡的详细信息
ipconfig /all
# 查看路由表
route print
route print -4 | findstr "0.0.0.0 172.16"
# 查看 网卡名称、网卡的接口编号（IF index）、网卡的mac地址 等信息
Get-NetAdapter
# 查看路由追踪
tracert -d 172.16.9.1
# 查看 网络连接
netstat -ano
netstat -ano | findstr "172.16.9 3389 7890"
# 添加一条路由规则, -p 是永久保存，不加 -p 重启后消失，需要再加
route ADD 172.16.0.0 MASK 255.240.0.0 172.16.19.254 IF 16 METRIC 5 -p
# 不需要时：删除路由规则
route DELETE 172.16.0.0 MASK 255.240.0.0 172.16.19.254 -p

```

Clash 配置（改完在 Party 里重载内核；不要手改 `work/config.yaml`）：

`mihomo.yaml`（TUN 排除内网，避免先被虚拟网卡截走）：

```yaml
tun:
  route-exclude-address:
    - 172.16.0.0/12
```

`profiles/19f8edde2a8.yaml`（直连出 USB；漏网的 172 绑回 WLAN）：

```yaml
- name: 🔗 全局直连
  type: select
  interface-name: 以太网 2

- name: 🌐 公司内网
  type: select
  interface-name: WLAN
  proxies:
    - DIRECT

rules:
  - IP-CIDR,172.16.0.0/12,🌐 公司内网,no-resolve
```

内网第一跳应是 `172.16.19.254`。
